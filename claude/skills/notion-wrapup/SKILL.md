# notion-wrapup — 로컬 작업을 노션 작업 페이지에 마무리하기

노션 독자는 이 컴퓨터의 파일도, 작업 중에 붙인 이름도 모릅니다. 노션 페이지는 로컬 작업의 목차가 아니라, 그것만 읽어도 이해되는 문서여야 합니다.

## 순서

1. **페이지를 읽는다.** `notion-fetch`로 대상 페이지와 상태, 문체("-한다"/"-합니다"), 기존 절을 확인합니다. 형제 작업 페이지 하나를 더 읽어 꼴을 맞춥니다.
2. **초안을 채팅에 먼저 보여 준다.** 사용자가 "draft first"라고 하지 않아도 노션에 쓰기 전에 초안을 보여 주고 확인을 받습니다. 분량은 사용자가 정한 만큼(예: "very dry and concisely")입니다.
3. **초안을 스스로 걸러 낸다.** 보여 주기 전에 다음을 확인합니다.
   - 로컬 경로가 없다. 파일을 보여 줘야 하면 첨부로 바꾼다(4번).
   - 작업 중에 붙인 이름(판 이름 "한 번 더 고친 판", 실행 이름, 조건 코드)이 없다. 무엇이 바뀌었는지를 그대로 쓴다.
   - 꺽쇠 괄호(U+300C·U+300D, 낫표)가 없다. 인용은 큰따옴표로 쓴다.
   - "결정"에는 사용자가 명시적으로 답한 것만 적는다. 제안과 시험하지 않은 구현 방식은 "제안(시험 안 함)"이나 "열린 문제"로 적고, 난이도를 단정하지 않는다.
   - 숫자는 원자료로 확인한 것만 쓴다.
4. **첨부할 파일을 정하고 올린다.** 초안의 "자료" 절에는 첨부할 파일의 이름과 한 줄 설명을 적어 함께 확인받습니다. 확인되면 파일마다:
   1. `notion-create-file-upload`를 `filename`으로 부른다.
   2. 돌려받은 `upload_url`과 `upload_headers`로 `scripts/upload.sh '<upload_url>' '<upload_headers JSON>' <파일>`을 실행한다.
   3. 본문에는 `<file source="file-upload://<id>"/>`를 넣는다. 업로드는 한 시간 안에 페이지에 붙여야 남는다.
   - 작은 텍스트 파일은 `notion-create-attachment`에 `content`로 바로 올려도 된다.
   - 첨부 이름은 독자가 알아볼 이름으로 바꾼다(예: `handoff-back-x.md` → `x 시험 결과.md`).
5. **쓴다.** 기존 내용은 지우지 않고 `insert_content`로 덧붙이거나, 고칠 곳만 `update_content`로 바꿉니다. 노션 쓰기 훅(`notion-local-path-gate.py`)이 경로나 꺽쇠 괄호를 막으면, 우회하지 말고 초안을 고칩니다.
6. **상태를 바꾼다.** 사용자가 마무리라고 했으면 "완료"로 바꾸고, 하지 않은 일이 있으면 본문에 "하지 않은 것"으로 남기고 응답에서 알립니다.
7. **알린다.** 응답에는 무엇을 붙였고 무엇을 첨부했는지, 상태를 무엇으로 바꿨는지를 짧게 씁니다.

## 하지 않는 것

- 확인 없이 노션에 쓰지 않습니다.
- 로컬 경로를 "자료"로 적지 않습니다. 첨부하거나, 필요 없으면 뺍니다.
- 작업 중 문서(handoff-back 등)를 독자용으로 다듬지 않은 채 붙일지는 사용자에게 묻습니다.
